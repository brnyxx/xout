## 1. 두 벤치마크가 이기는 방식

| 축 | ouroboros | paperthin | xout 현재 |
|---|---|---|---|

| 설치 | 플랫폼별 한 줄 + `ooo setup` | `npx skills@latest add ... --global --agent '*'` 한 줄 | `uvx xout` (PyPI 미배포로 아직 죽은 명령) |
| 시각 증명 | 5개 호스트 실동작 GIF 그리드 | 배너 SVG + 2x2 개념 매트릭스 | 터미널 GIF 1개 (신작 완료) |
| 콘텐츠 구조 | 철학(소크라테스)→수학(모호도 수식)→아키텍처(18패키지) 3층 피라미드 | The Map(2x2) → Index(20 스킬 표) → Problem(5) → Fixes(15) | 훅 → How → 신뢰 → 접힘 |

| 안전 신호 | 법적 고지, MCP 버전 경고 | 스킬 표에 invoker(model/user)와 read-only(✔) 컬럼 | boundary 산문 |
| 확산 장치 | 10+ 런타임 지원, 후원/활동 뱃지 | 10개 언어 README, 이모지 스킬 코드 | ko/en 2개 |

핵심 관찰:

- **ouroboros의 무기 = 깊이의 피라미드.** 5분 설치층 아래에 수식과 아키텍처 층이
  실재해서 "장난감이 아니다"를 증명한다.
- **paperthin의 무기 = 증거 우선 + 절제의 반서사.** 모든 주장 뒤에 "실제로 이 버그가
  났었다"는 [PROOF]가 접혀 있고, "더하기가 아니라 덜어내기"라는 반직관 철학이
  엔지니어 정서를 정확히 때린다.
- 둘 다 **자기 산출물이 사용자에게서 측정된 것은 아니다.** ouroboros는 인터뷰 답변을,
  paperthin은 저자의 경험을 컴파일한다. **사용자의 실제 반증 행위에서 규칙을
  컴파일하는 도구는 xout뿐이다.** 이게 우리가 파야 할 해자다.

## 2. xout이 둘을 넘는 설계: "증거 있는 규칙"

paperthin의 [PROOF]를 개인화하면 xout의 킬러가 된다:

> paperthin: "이 패턴이 옳다 - 저자가 겪은 버그가 증거다."
> xout: "이 규칙이 네 것이다 - **네가 그은 X가 증거다.**"

구체 형태 - **`xout why` 명령 (신설)**:

```
$ xout why autonomy
규칙: 되돌릴 수 있는 변경은 먼저 실행하고 보고한다. 되돌리기 어려운 작업은 먼저 확인받는다.
근거: 2026-09-01 세션 a3f2
  - 버그픽스 장면에서 "시작해도 될까요?"에 X (slot 1)
  - 고위험 장면에서 "이미 실행했습니다"에 X (slot 12)
  -> 두 장면이 갈려서 조건부로 컴파일됨
상태: 판별시험 통과 / 마지막 재확인 7일 전
```

모든 규칙이 자기 증거를 갖고, XOUT.md의 각 줄이 manifest의 strike 이벤트로
소급된다(데이터는 이미 원장에 있다 - 노출 명령만 없었다). README의 [PROOF]
접힘에는 실제 세션의 이벤트 체인을 인용한다.

## 3. 확정 경로 (순서 제안)

### Phase A - 콘텐츠 코어 대수술 (해자 구축)
- 축 개편: commit 분리, verification/dependency_policy 신설, response_language/verbosity 정리
- 장면 1→3 (버그픽스/신규기능/고위험): 조건부 규칙을 긋기 증거에서 컴파일
- **`xout why <axis>`**: 규칙→증거 소급 명령 (paperthin PROOF의 개인화)
- 산출: "설문이 아니라 측정, 주장이 아니라 증거"가 제품 문장으로 성립

### Phase B - 표면 고도화 (두 벤치마크 문법 합성)
- README 3층 피라미드: [설치+GIF] → [The Map: 8축 x 3장면 매트릭스 SVG + 문제→해법 서사] → [수학(가설공간·판별시험)과 원장 아키텍처]
- 스킬/명령 표에 paperthin식 안전 신호 컬럼: 쓰기 대상(없음/소유 디렉토리/CLAUDE.md 1줄), 동의 필요 여부
- 사이트 전면 리디자인 (터미널 미학, 동일 서사)
- 다국어: en/ko 완결 후 확장

### Phase C - 마찰 제로 배포
- PyPI 정식 업로드 (`uvx xout`을 살아있는 명령으로) + 플러그인 마켓플레이스
- EN 런타임 팩 (글로벌 확산 전제)
- 런치 킷 (Show HN / 트위터 스레드, GIF 2-3종: 터미널/대화형 플러그인)

의존성: A → B → C. B의 [PROOF]와 Map이 A의 산출물(조건부 규칙, why 명령)을
인용해야 하므로 A가 먼저다.
